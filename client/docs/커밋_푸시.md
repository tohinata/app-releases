# 커밋 · 푸시 정책

- **금지: rebase · force · discard.** 충돌은 `git pull --rebase origin <브랜치>` 로 합친 뒤 올린다.
- 커밋은 작게·자주. 메시지는 사용자가 읽을 한국어 한 줄(그대로 체인지로그가 됨).
- `… 릴리스` / `릴리스 - 버전 올림` 은 버전 커밋 전용(자동 체인지로그에서 제외) — 일반 작업에 쓰지 말 것.

## bat
`3-1_커밋+올리기`(확인 후 add→commit→push) · `3-2_커밋만` · `3-3_올리기만` · `0-1_깃허브처음연결`.
`4-1_새버전배포` 는 배포 전 미커밋 변경을 먼저 커밋하고, 끝에 버전·CHANGELOG 커밋/푸시까지 자동.

## 서명 키 백업 (중요)
- 앱마다 릴리스 키 1개, 첫 배포 때 자동 생성. 안드로이드: `keystore/<앱키>-release.jks` + `keystore.properties`(비번 포함). 둘 다 git 제외.
- **잃으면 앱을 지우지 않는 한 업데이트 불가(서명 불일치).** 반드시 따로 백업. dname: `CN=tohinata, O=coarsoft, C=KR`.

## 인코딩
소스·문서·manifest·CHANGELOG = UTF-8(BOM 없음) / `tools/common.ps1` 류 = UTF-8(BOM 있음, PS 5.1 한글) / `*.bat` = CP949(`배치파일.md`).
