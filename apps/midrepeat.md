### [0.12.0 — 2026-09-30 (최신)](https://github.com/tohinata/app-releases/releases/tag/midrepeat-v0.12.0)

#### Added
- **녹음 다시 듣기.** 따라 말하기에서 `자막 → 녹음 → 내 녹음 듣기` 차례일 때, 따라 말하기 팝업 아래에
  `⟲ 다시 듣기` 팝업이 하나 더 뜬다. 누르면 방금 녹음을 처음부터 다시 듣는다 (몇 번이든).
  다 들으면 여느 때처럼 다음 재생으로 넘어간다
  - 따라 말하기 팝업이나 영상을 누르면 예전처럼 듣기를 끝내고 바로 넘어간다

#### Changed
- 자막 목록 줄마다 있던 **녹음(🎤) 아이콘을 뺐다.** 녹음은 가장 최근 한 개만 남고, 이제는 들은 자리에서
  다시 들을 수 있어서 목록에서 찾아 들을 일이 없다. 줄 오른쪽은 학습 종료 · 북마크만 남는다

#### Fixed
- 내 녹음을 듣는 동안 팝업의 **진행 막대가 가득 찬 채 멈춰 있던 것.** 이제 녹음 재생 위치를 따라 차오르고,
  남은 시간(초)도 함께 줄어든다

### 0.11.1 — 2026-09-30

#### Fixed
- **동기화 파일이 드라이브가 아니라 폰 안(다운로드 등)에 만들어지던 문제.**
  파일 선택 화면은 보통 `다운로드` 나 `최근` 에서 열려서, 그대로 저장하면 파일이 이 폰에만 생기고
  드라이브로 올라가지 않았다. 앱은 파일을 직접 올리지 않는다 — 드라이브에 있는 파일이어야 드라이브 앱이 올린다
  - 고른 파일이 폰 저장공간(내장 메모리 · 다운로드 · 미디어 · 삼성 내 파일)이면 연결하기 전에 알리고
    `Drive 에서 다시 고르기` 를 권한다 (`그래도 이 파일 쓰기` 도 있다)
  - 카드에 파일이 있는 곳을 보인다: `Google 드라이브 · ttaramal-sync.json · 마지막 동기화 방금`.
    폰 저장공간이면 빨간 글씨로 다른 폰과 동기화되지 않는다고 알린다

### 0.11.0 — 2026-09-30

#### Added
- **다른 기기와 학습 시간 동기화.** 홈 화면 맨 아래 `다른 기기와 학습 시간 동기화` 카드.
  - `동기화 파일 연결` → 안드로이드 파일 선택 화면에서 **Drive** 를 골라
    첫 기기는 `ttaramal-sync.json` 을 새로 만들고, 두 번째 기기부터는 그 파일을 고른다
  - 앱은 그 파일만 읽고 쓴다. 올리고 받는 일은 드라이브 앱이 한다 — **인터넷 권한 · 구글 로그인 없음**
  - 합치는 것은 **학습 시간만**: 이번 주 · 연속 · 전체, 학습 기록(7가지 보기 모두), 주로 공부하는 시간대가
    모든 기기의 합으로 보인다. 영상 · 최근 영상 · 이어보기 위치 · 북마크 · 학습 종료 마크 · 녹음 ·
    설정은 기기마다 따로다 (폰마다 가진 영상이 다르므로)
  - 카드에 파일 이름 · 마지막 동기화 시각, 기기별 전체 학습 시간(이 기기 / 다른 기기와 그 기기가 마지막으로 쓴 때),
    `지금 동기화`, `연결 해제`
  - 동기화 시점: 홈 화면에 올 때(15초 안에 다시 오면 건너뜀), 영상 화면을 떠날 때, `지금 동기화`.
    바뀐 게 없으면 파일에 쓰지 않는다 (드라이브가 매번 올리지 않게)
  - 연결 해제하면 파일과 이 기기 기록은 그대로 두고, 다른 기기 시간만 합계에서 빠진다

#### Design notes
- 파일 안에 **기기마다 칸이 하나** 있고 각 기기는 자기 칸만 고친다. 홈 화면은 칸을 모두 더한다.
  기기 구분은 앱이 처음 만든 무작위 번호(앱을 지우고 다시 깔면 새 번호 — 그 전 기록은 다른 기기로 남아 합계는 유지)
- 기록은 늘기만 하므로 같은 칸의 두 사본은 **시각별로 큰 값**을 남긴다.
  두 기기가 거의 동시에 써서 한쪽이 옛 사본으로 덮여도, 그 기기가 다음에 동기화할 때 제 기록으로 되살린다.
  다른 기기 기록도 앱 안에 받아 두고(`sync_devices.json`), 파일이 옛 사본이면 받아 둔 쪽으로 고쳐 쓴다
- **다른 앱의 파일을 잘못 골라도 덮어쓰지 않는다** — 빈 파일이거나 `"app": "ttaramal"` 이 있는 파일만 쓴다.
  아니면 카드에 빨간 글씨로 알리고 손대지 않는다
- 권한이 사라졌거나 파일이 지워졌으면 다시 연결하라고 알린다
- 드라이브 파일 선택 화면에 따라 새 파일 이름 뒤에 ` (1)` 이 붙을 수 있다. 이름은 상관없다
- JSON 은 작은 자체 구현(`MiniJson`) — 합치기 규칙을 안드로이드 없이 단위 테스트하려고

#### 검증
- 단위 테스트 `StudySyncTest` 추가 (빈 파일 · 다른 앱 파일 거절 · 두 기기 합계 · 옛 사본 덮어쓰기 복구 ·
  받아 둔 기록으로 복구 · 잘못된 줄 건너뛰기 · JSON 왕복). 앱 코드 컴파일 오류 없음.
  실제 드라이브 파일로 두 폰 사이 동기화는 아직 해 보지 못했다

### 0.9.0 — 2026-09-30

#### Added
- **따라 말하기 중 화면을 누르면 건너뛰기.** 대기 중에는 영상(과 자막)을 한 번 누르면 바로 다음 재생으로
  넘어간다. **이때는 조작부 메뉴가 열리지 않는다** — 건너뛰려다 메뉴가 뜨면 번거롭다
- **자막 목록 맨 앞에 No. 열** — 자막 번호. 북마크만 · 완료 숨김으로 걸러도 원래 번호 그대로
- **녹음.** 목록 머리의 `🎤 녹음` 을 켜면 따라 말하기 대기 동안 마이크로 녹음하고,
  대기가 끝나면 **방금 녹음한 내 목소리를 들려준 뒤** 다음 재생으로 간다
  - 흐름: `자막 재생 → 따라 말하기(녹음) → 내 녹음 듣기 → 자막 재생 → …`
  - 팝업에 `● 녹음 중` / `▶ 내 녹음 듣는 중` 이 뜬다. 녹음 중에 누르면 녹음을 끝내고 바로 듣기,
    듣는 중에 누르면 듣기를 건너뛴다
  - 줄마다 가장 최근 녹음 하나를 남긴다. 목록의 🎤(빨간색 = 녹음 있음)를 누르면 그 줄의 녹음을 다시 듣는다
  - 처음 켤 때 마이크 권한을 묻는다. 대기 시간이 0초면 녹음할 틈이 없어서 알려준다
- **백그라운드 재생** (위쪽 🎧). 켜면 화면을 끄거나 다른 앱으로 가도 재생 · 반복 · 따라 말하기가 이어진다.
  알림에 재생/일시정지 · 끄기 버튼. 다시 누르면 끈다
  - 녹음은 화면이 보일 때만 한다 (백그라운드에서는 대기만)
- **취침 모드** (위쪽 🌙). 10 · 15 · 30 · 45 · 60 · 90분 뒤 멈춘다. **마지막 20초는 소리를 서서히 줄인다.**
  남은 분이 아이콘 옆에 뜬다. 켜면 백그라운드 재생도 같이 켠다 (화면이 꺼져도 들리게)

#### Changed
- **반복 몇 번째인지는 따라 말하기 팝업에서만 보여준다.** 팝업에 `따라 말하기 · 2 / 3  7.3` 처럼
- 자막 목록의 `쉼` · `1/3` 배지를 없앴다 (목록이 계속 깜빡이며 바뀌었다)
- 목록 위쪽의 `4번 · 1/3` · `4번 · 따라 말하기` 상태 표시를 없앴다
- 목록 머리를 두 줄로 — 윗줄 자막 정보, 아랫줄 `녹음 · 북마크만 · 완료 숨김` (옆으로 넘김)

#### Design notes
- 녹음 · 녹음 듣기도 **따라 말하기 대기의 일부**로 다룬다. 반복 엔진은 그동안 계속 "대기 중" 이라
  위치를 받아도 아무것도 하지 않고, 대기가 끝나는 곳(`finishGap`)에서만
  녹음 끝 → 듣기 → 이어서 재생 순으로 넘어간다. 다른 줄을 누르거나 탐색하면 녹음 · 듣기도 같이 멈춘다
  (녹음 중이던 것은 버린다)
- 녹음 파일은 앱 폴더 `recordings/<영상+자막>/<줄 시작 ms>.m4a`. 녹음 중에는 `.part` 로 쓰다가
  끝나면 이름을 바꾼다 (중간에 끊겨도 반쪽 파일이 남지 않게). 0.4초 미만은 버린다
- 백그라운드 재생은 포그라운드 서비스(mediaPlayback)가 알림만 맡고, 플레이어는 여전히 영상 화면이
  들고 있다. 영상 화면을 닫으면(뒤로) 재생도 서비스도 끝난다. 화면이 꺼져도 멈추지 않게 wake lock 을 건다
- 반복 엔진에 `gapPass`(대기 직전에 몇 번째로 들었는지)를 더했다 — 대기에 들어가면 `pass` 는 이미
  다음 바퀴를 가리키므로 따로 들고 있어야 팝업에 맞는 숫자가 나온다

#### 검증
- 앱 코드 컴파일 오류 없음, 테스트 **38개 통과** (반복 엔진 테스트에 `gapPass` 확인 추가)
- 녹음 · 알림 · 화면 끈 상태 재생 · 취침 모드는 폰에서만 확인할 수 있어 아직 보지 못했다

### 0.8.0 — 2026-09-29

#### Added
- **학습 종료 표시.** 자막 목록의 줄마다 ☆ 옆에 ✓ — 누르면 초록 ✓ 로 바뀌고 줄이 흐려진다
  - **반복이 다음 줄로 넘어갈 때 학습 종료한 줄은 건너뛴다.** 이전 / 다음 자막 버튼,
    탐색으로 옮긴 뒤 반복이 붙을 줄도 마찬가지 — 다 익힌 문장은 다시 돌지 않는다
  - **지금 반복 중인 줄을 학습 종료하면 바로 다음 줄로 넘어간다** (재생 · 따라 말하기 대기 중일 때).
    남은 줄이 없으면 멈추고 알려준다
  - 목록에서 직접 누른 줄은 학습 종료했어도 재생한다 (복습하고 싶을 때)
  - 목록 머리의 `✓ 완료 숨김` 을 켜면 학습 종료한 줄을 목록에서 뺀다. 옆에 개수

  - 북마크는 **영상 + 자막(트랙 · 파일)마다** 따로 기억한다
  - 최근 목록에서 영상을 지우면 그 영상의 북마크도 같이 지운다

#### Design notes
- **줄을 번호가 아니라 시작 시각으로 기억한다.** 번호는 자막을 다시 읽을 때 바뀔 수 있지만
  시각은 그대로다. 같은 영상이라도 영어 자막과 한국어 자막은 줄의 시각이 달라서
  섞으면 엉뚱한 줄에 별이 붙으므로 자막마다 따로 둔다
- **"다음 자막" 을 누가 정하는지 `RepeatEngine` 밖으로 뺐다** (`nextOf`). 엔진은 여전히
  플레이어도 북마크도 모르고, ViewModel 이 "다음은 몇 번" 만 알려준다
- 목록은 북마크만 볼 때 위치(position)와 자막 번호가 달라진다. 목록 어댑터 바깥과는
  항상 자막 번호로 이야기하고, 위치로 바꾸는 일은 어댑터 안에서만 한다
- 북마크가 하나도 없는데 `북마크만` 을 켜면 빈 목록에 방법을 안내한다.
  반복은 평소처럼 다음 줄로 간다 (갈 곳이 없어 멈추는 것보다 낫다)

#### 도구

  dist 폴더를 연다. `build-apk.bat debug` 는 디버그 APK
  - **배포용 서명 키를 처음 실행 때 한 번 만든다** (`keystore\midrepeat-release.jks`,
    비밀번호는 `keystore.properties`). 둘 다 `.gitignore` 에 넣어 GitHub 에 올라가지 않는다.

  - `app/build.gradle.kts` 는 `keystore.properties` 가 있을 때만 release 에 서명을 붙인다 —
    키가 없는 PC 에서도 debug 빌드와 Android Studio 는 그대로 된다
  - install.bat(디버그 서명)으로 깔린 앱 위에는 release APK 가 설치되지 않는다.

    가운데 두 번 탭으로 건너뛴다** — 반복 횟수는 그대로 이어진다
  - 목록에서 다른 줄을 누르거나 탐색하면 대기는 취소된다

#### Changed
- **반복 재생의 체감이 달라진다.** 기본 대기가 10초이므로, 예전처럼 붙여서 들으려면
  반복 설정에서 따라 말하기 대기를 `0` 으로 두면 된다

#### Design notes
- **마지막 바퀴 뒤에도 기다린다** (다음 자막으로 넘어가기 전). 받아쓰기 스튜디오는 마지막 바퀴
  뒤에 쉬지 않지만, 쉐도잉은 마지막으로 들은 직후가 가장 따라 말하기 좋은 때다.
  단, 반복 후 동작이 `멈춤` 이거나 마지막 자막이면 기다리지 않고 바로 멈춘다 —
  멈춰 있는 동안 얼마든지 따라 말할 수 있다
- **대기가 시작될 때 다음 재생 위치로 미리 이동해 둔다.** 기다리는 동안 버퍼링이 끝나서
  대기가 끝나면 바로 소리가 난다. 그래서 화면 자막은 재생 위치가 아니라 '방금 들은 줄' 을 따로 들고 있다
- **대기 판단도 `RepeatEngine` 이 한다** (`Action.Gap`). 대기 중에는 위치를 받아도 아무것도
  하지 않는다 — 멈춰 있어 위치가 구간 끝에 머무르므로, 그냥 두면 매번 "한 바퀴 끝" 으로 읽힌다.
  시간 재기는 ViewModel 이 '끝나는 시각' 을 들고 한 번만 예약한다
- **화면을 떠나면 대기를 접는다.** 타이머가 살아 있으면 백그라운드에서 재생이 다시 시작된다.
  다음 재생 위치에 멈춘 채로 두므로 돌아와서 재생을 누르면 이어진다
- 대기 중에도 화면이 꺼지지 않게 한다 (30초 대기는 화면 자동 꺼짐 시간보다 길 수 있다)

#### 검증

  전체 **17개 통과**, 앱 코드 컴파일 오류 없음

### 0.1.0 — 2026-09-29

첫 버전. 받아쓰기 스튜디오(Windows) 의 「미드 받아쓰기」 식 구간 반복을
안드로이드로 옮기되, **받아쓰기는 빼고 자막 한 줄씩 반복해서 듣기**에 집중했다.

#### Added
- **자막 읽기**
  - MKV 에 **내장된 글자 자막**(SRT / ASS / SSA / WebVTT)을 ffmpeg 없이 직접 읽는다.
    트랙이 여러 개면 파일을 **한 번만** 훑어서 전부 읽어두고, 언어를 바꿀 때 다시 훑지 않는다
  - 외부 자막 파일 `.srt` `.smi` `.vtt` `.ass` `.ssa` 불러오기
  - SMI 는 **CP949 / EUC-KR 을 자동 판별**하고, 한 파일 안의 여러 언어
    (`KRCC` `ENCC` …)를 각각 따로 고를 수 있다. `<STYLE>` 의 이름(한국어, English)을 목록에 붙인다
  - 영상마다 마지막으로 고른 자막을 기억한다 (외부 파일은 다음에도 열 수 있게 권한을 붙잡아 둔다)
- **자막 목록** — 전체 자막을 시간과 함께 나열. 재생 중인 줄을 강조하고 자동으로 따라 내려간다.
  목록을 손으로 넘기는 중이면 3초 동안 자동 스크롤을 멈춘다. 줄을 누르면 그 줄부터
- **자막 단위 반복**
  - 한 줄을 **1 ~ 20회 또는 무한** 반복
  - **앞 여유 / 뒤 여유** 0 ~ 2초 (0.05초 단위) — 말머리·말꼬리가 잘리지 않게
  - 다 돌면 **다음 자막으로** 또는 **멈춤**
  - 반복 중인 줄 옆에 `2/3` 처럼 몇 번째 바퀴인지 표시
- **플레이어 (MX 플레이어 방식)**
  - 화면을 누르면 조작부가 나타나고 재생 중이면 3.5초 뒤 숨는다
  - 두 번 탭: 왼쪽 10초 뒤로 / 가운데 재생·정지 / 오른쪽 10초 앞으로
  - 좌우로 끌어 탐색(손을 떼면 이동), 왼쪽 위아래 밝기, 오른쪽 위아래 볼륨
  - **배속 0.25 ~ 5.0배** (0.05 단위, 음정 유지). 자주 쓰는 값은 버튼으로
  - **화면 비율** 맞춤 / 늘리기 / 확대 / 16:9 / 4:3 / 21:9 — 버튼을 누를 때마다 다음 것으로
  - **화면 회전** 자동 / 가로 고정 / 세로 고정.
    세로는 위 영상 + 아래 자막 목록, 가로는 영상 전체 + 목록 버튼으로 옆 패널
- **자막 모양** — 크기, 위치, 글자색, **배경 사용 여부 / 배경색 / 배경 불투명도**, 그림자.
  영상 위에서 두 손가락으로 크기, 자막을 끌어서 위치를 바로 바꿀 수도 있다
- **첫 화면** — 영상 열기, 최근 본 영상(이어보기 위치 표시, 길게 눌러 지우기)
- **AC3 / DTS 음성** — 폰에 디코더가 없는 경우가 많아 FFmpeg 오디오 디코더를 넣었다
- **앱 아이콘** — 재생 버튼을 감싼 반복 화살표 + 자막 막대. 적응형 아이콘이고,
  Android 13 이상의 테마 아이콘(한 색) 버전을 따로 두었다
- **install.bat** — USB 로 연결한 폰(개발자 모드)에 빌드·설치·실행까지 한 번에.
  빌드가 몇 분 걸릴 수 있어서 **폰 연결부터 확인**하고 시작한다
- **push.bat** — 받아쓰기 스튜디오의 것과 같은 방식. 올라갈 커밋을 보여주고 한 번 묻고 올린다

#### Design notes
- **MKV 파서는 받아쓰기 스튜디오의 `MatroskaReader` 를 옮기면서 세 가지를 고쳤다.**
  - 원본은 블록마다 본문 전체를 읽은 뒤에 트랙 번호를 봤다. 영상·음성이 파일의 거의 전부라
    결국 파일을 통째로 읽는 셈이었다. 이제 **트랙 번호만 먼저 읽고** 자막이 아니면 건너뛴다.
    2.6GB MKV 에서 자막 150줄을 읽는 데 약 0.5초(PC)
  - **크기 미정 클러스터**(스트리밍용으로 만든 MKV)를 처리한다.
    원본은 크기를 "파일 끝까지" 로 잡아 첫 클러스터 뒤를 전부 건너뛰었다
  - 자막 트랙 **압축**(zlib, header stripping)을 푼다
- **자막은 플레이어가 그리지 않고 앱이 직접 그린다.** 위치·크기·배경을 마음대로 바꾸려면
  그 편이 낫고, 반복 판단에 쓰는 자막 목록과 화면의 자막이 항상 같은 데이터가 된다.
  그래서 플레이어의 자막 트랙은 아예 꺼둔다
- **반복 판단(`RepeatEngine`)은 플레이어를 만지지 않는다.** 재생 위치를 받아
  "여기로 이동" / "멈춤" 만 돌려준다 — 그래서 단위 테스트가 된다.
  판단 주기는 구간 끝까지 남은 시간 ÷ 배속으로 잡는다 (5~40ms). 5배속에서 고정 50ms 로
  보면 구간 끝을 250ms 씩 넘겨 다음 문장 첫소리가 들린다
- **화면 회전 때 Activity 를 다시 만들지 않는다** (`configChanges`). 영상 표면이 끊기지 않게
  한 레이아웃 안에서 배치만 가로/세로로 바꾼다. 플레이어는 ViewModel 이 들고 있다
- **화면은 View 로 만들었다.** 영상 표면(SurfaceView)·제스처·자막 레이어를 직접 겹쳐
  다루는 화면이라 이쪽이 단순했다
