### [0.9.1 — 2026-09-29](https://github.com/tohinata/app-releases/releases/tag/middictation-v0.9.1)

#### Added
- **학습 종료 마크.** 북마크와 담는 것은 같지만 뜻이 반대다 —
  북마크는 '또 볼 것', 이건 **'이제 안 볼 것'**
  - 표시한 문장은 **자동 진행과 앞뒤 이동(`F2` · `F3`)이 건너뛴다.**
    다 익힌 문장에서 열 번씩 다시 멈추지 않게 하는 것이 이 기능의 전부다
  - `F9`, 받아쓰기 탭의 `[○ 학습 종료]`, 자막 목록의 `○` 버튼, 우클릭 메뉴 — 네 곳에서 토글
  - 표시한 줄은 자막 목록에서 **흐리게** 남는다. 지워버리면 되돌릴 방법이 안 보인다
  - 별표 옆에 나란히 서므로 **색으로 갈랐다** — 별표는 `Warn`(또 볼 것), 체크는 `Ok`(다 익힌 것)
- **[학습 종료] 탭.** 표시한 문장을 모아 본다 (전체 / 이 영상)
  - 더블클릭이나 우클릭 메뉴로 그 문장으로 간다. **목록에서 직접 고르는 것은
    건너뛰기와 무관하게 언제나 통한다** — 건너뛰면 클릭이 먹지 않는 것처럼 보인다
  - `Ctrl`·`Shift` 로 여러 개 골라 `Del` 로 해제
  - `[이 영상 전체 해제]` — 체크 버튼이 목록에 촘촘히 있어서 여러 줄을 잘못 누르는 일이 잦다
- 설정 &gt; 재생 &gt; **학습 종료로 표시한 문장은 건너뛰기** (기본 켬).
  끄면 표시는 남고 건너뛰지만 않는다

#### Design notes
- **건너뛰기를 자동 진행과 수동 이동에 함께 걸었다.** 자동에만 걸고 `F2`/`F3` 은
  그대로 두는 쪽도 생각했는데, 규칙이 둘이 되면 "왜 여기서는 건너뛰고 저기서는
  안 건너뛰나" 를 매번 따져야 한다. 규칙은 하나여야 예측이 된다.
  목록에서 직접 고르는 것만 예외다
- **막혔을 때 이유를 말한다.** 뒤쪽이 전부 학습 종료면 `마지막 문장입니다` 가 아니라
  `뒤쪽은 모두 학습 종료로 표시돼 있습니다` 라고 적는다. "왜 안 넘어가지" 로 끝나면
  설정에 있는 스위치를 찾을 길이 없다
- **`DoneButton` 스타일은 `StarButton` 을 물려받지 않는다.** 물려받으면 그쪽의
  `IsBookmarked` 트리거까지 같이 와서, 북마크한 줄의 체크 버튼이 노란색으로 변한다.
  템플릿만 같고 트리거는 따로 가야 한다
- **메모 칸을 두지 않았다.** 남길 말이 있으면 북마크에 담는 편이 맞다.
  '이제 안 볼 것' 에 메모를 붙이는 것은 앞뒤가 맞지 않는다

### 0.9.0 — 2026-09-29

#### Added
- **학습 기록을 일곱 가지 모양으로.** 잔디밭 하나뿐이던 것을 골라 볼 수 있게 했다.
  홈 화면 기록 패널 머리의 목록에서 바로 고르고, 설정 &gt; 화면 에도 같은 항목이 있다

  | 모양 | 어떻게 보여주나 |
  |---|---|
  | **잔디밭** | 지금까지의 것. 1년치를 한눈에 |
  | **스티커 달력** | 한 달 달력에 공부한 날마다 도장. 🌱 조금 → 🌿 → 🌸 → ⭐ 많이 |
  | **자라는 화분** | 한 주가 화분 7개짜리 선반 한 줄. 공부량만큼 새싹에서 꽃까지 자란다 |
  | **필름 스트립** | 한 달을 필름 한 줄로. 공부한 날일수록 선명하게 '현상' 된다 |
  | **별자리** | 공부한 날마다 별 하나. 연속한 날끼리 선으로 이어진다 |
  | **캐릭터 성장** | 누적 시간으로 알 → 병아리 → 닭. 아래에 최근 30일 발자국 |
  | **한 주 도장판** | 요일 7칸을 다 채우면 완주 배지 ★. 지난 배지도 모아 보여준다 |

  - 달력·필름은 `◀ ▶` 로 **지난 달**을 넘겨 본다 (기록을 400일치 읽어두므로 그 범위 안에서)
  - 스티커 달력과 도장판에서 **오늘 도장이 방금 찍히면 '쿵'** 하고 내려앉는다.
    창 크기를 바꿀 때마다 튀지 않게, 한 번만 보여준다
  - 모든 모양이 칸마다 툴팁으로 `날짜 · 공부 시간` 을 보여준다
- `commit.bat` 추가 — 바뀐 파일과 줄 수를 먼저 보여주고, 메시지를 받아 커밋한다.
  `commit.bat "0.9.1 무엇을 고쳤는지"` 처럼 메시지를 바로 줄 수도 있다.
  **올리지는 않는다** — 그건 `push.bat` 의 일이다
- `push.bat` 추가 — 올라갈 커밋을 먼저 보여주고 한 번 물어본 뒤 GitHub 에 올린다.
  커밋·리베이스·강제 푸시는 **하지 않는다** — 확인 없이 히스토리를 고치는 일을
  배치 파일에 맡기면, 잘못됐을 때 무엇이 어떻게 된 건지 알 수 없다

#### Design notes
- **일곱 개가 모두 같은 데이터 하나만 읽는다** — `날짜 → 그 날 공부한 초`.
  모양마다 따로 모으는 값이 없으므로, **기록이 쌓인 뒤에 바꿔도 그동안의 기록이
  그대로 새 모양으로 나온다.** 모양을 바꾸는 것이 기록을 버리는 일이 되면
  아무도 바꿔보지 않게 된다. 이게 이 구조를 고른 이유다
- **고르는 자리를 설정 창이 아니라 기록 패널 머리에 뒀다.** 모양을 고르는 일은
  '보면서' 하는 것이다. 설정 창을 여닫으며 비교하게 만들면 결국 아무도 바꿔보지 않는다.
  (설정 창에도 같은 항목을 둬서, 설정을 훑는 사람도 이 기능이 있다는 걸 알게 했다)
- **기본값은 잔디밭 그대로.** 업데이트했다고 화면이 저절로 바뀌면 놀란다
- **색은 그릴 때마다 테마 사전에서 가져온다.** 코드로 만든 요소는 `DynamicResource`
  가 듣지 않아 색을 한 번 박으면 테마를 바꿔도 예전 색이 남는다 (0.8.21 에서 겪은 일).
  일곱 모양 전부 같은 규칙을 따른다
- **밤하늘만 예외로 두 테마에서 다 어둡다.** 별자리는 어두운 바탕이 전제인 그림이라
  라이트 테마에서 밝게 그리면 별이 보이지 않는다. 영상 위 표시에 쓰는 `OverlayBg` 를
  썼고, 별도 잔디색이 아니라 흰색 계열 + 가장 큰 단계만 금색으로 했다
- **이모지는 단색으로 쓴다.** WPF 는 Segoe UI Emoji 를 단색 글리프로 그린다.
  그래서 모양은 이모지에서, 색은 단계별로 코드에서 넣는다 —
  컬러 이모지를 기대하면 라이트·다크 어느 쪽에서도 색을 맞출 수 없다
- **모양을 바꾸면 달 위치는 이번 달로 되돌린다.** 필름에서 3월을 보다가 달력으로
  바꿨을 때 3월이 그대로 뜨면, 바뀐 것이 모양인지 날짜인지 헷갈린다

### 0.8.28 — 2026-09-29

#### Added
- **반복 사이에 따라 말할 시간.** 여태 반복은 쉼 없이 붙어서 돌았다 —
  들리는 동안 같이 말하거나, 다 듣고 나서 급히 말하는 수밖에 없었다.
  이제 한 바퀴가 끝나면 **멈춰서 기다린다**
  - `재생 → 쉼 → 재생 → 쉼 → …`. 10회 반복이면 **아홉 번** 쉰다
  - **0 ~ 30초, 기본 10초.** `0` 이면 예전처럼 쉬지 않고 바로 다음 바퀴
  - 받아쓰기 탭의 `연습` 슬라이더(반복 횟수 바로 옆)와
    설정 &gt; 재생 &gt; 구간 반복 두 곳에 있고 서로 연동된다
  - **쉬는 동안 영상 가운데에 남은 시간이 뜬다.** 0.1초 단위 카운트다운 + 진행 바.
    OSD 를 쓰지 않은 이유 — OSD 는 0초로 끌 수 있고 스스로 사라지는데,
    이건 '지금 기다리는 중' 이라는 상태 표시라 쉬는 동안 떠 있어야 한다
  - **`Space` 로 쉼을 건너뛴다** (받아쓰는 중이면 `Ctrl+Space`).
    여기서 반복을 끊지 않는 것이 중요하다 — 열 번 듣기로 걸어둔 것이
    한 번에 풀려버리면 쓸 수가 없다. '됐어, 다시 들려줘' 라는 뜻으로 쓴다
  - 마지막 바퀴 뒤에는 쉬지 않는다. 그때는 '끝나면 다음 문장' 이 이미 정해져 있다
  - 자막 구간 · 여러 줄 이어 듣기 · A-B · [구간 반복] 탭 **모두** 같게 적용된다

#### Changed
- **기본값이 10초이므로 반복 재생의 체감이 달라진다.** 예전처럼 붙여서 들으려면
  받아쓰기 탭의 `연습` 을 `0` 으로 두면 된다 (`쉼 없음` 으로 표시된다)

#### Design notes
- **쉼은 '멈춰 기다리기' 로 구현했다.** 남은 시간을 tick 마다 깎지 않고
  *끝나는 시각* 을 들고 있는다 — tick 간격이 정확히 30ms 가 아니라 깎아 나가면
  오차가 쌓인다
- **쉬는 동안에는 tick 에서 곧바로 빠져나온다.** 멈춰 있어서 `Player.Time` 이
  구간 끝에 머무르므로, 구간 판정을 그냥 지나가면 매 tick 이 "한 바퀴 끝났다" 로
  읽혀 반복 횟수가 순식간에 다 깎인다
- **재생 버튼 모양을 쉼 시작 때 직접 ▶ 로 바꾼다.** 위치 갱신이 멈춰 있어
  ❚❚ 로 남으면 지금 도는 중인 줄 알게 된다

### 0.8.26 — 2026-09-21

두 가지 모두 "지금 무슨 상태인지 화면이 말을 안 해준다" 는 같은 병이었다.

#### Fixed
- **A-B 를 잡는 중인지 아닌지 알 수 없던 문제.** `A` `B` `✕` 버튼 셋이
  어떤 상태에서도 똑같이 생겨서, 'A 를 찍어둔 상태' 를 눈으로 확인할 방법이 없었다.
  이제 **세 군데가 같은 얘기를 한다** —
  - **버튼 색** — 이미 찍은 지점은 강조색으로 **채우고**, 이번에 누를 차례는
    강조색 **테두리**로. `A` 를 찍기 전에는 `B` 가 아예 **비활성**이다
    (눌러도 거절당할 버튼을 켜두면 "왜 안 먹지" 를 한 번 겪어야 한다)
  - **옆의 글자** — `A 00:01:23 — 끝날 지점에서 B ( ] )` /
    `⟳ 00:01:23 ~ 00:01:31 (8.0초)`. 상태마다 색도 다르다
  - **타임라인의 띠** — 재생 바 위에 A·B 지점과 그 사이 구간을 그린다.
    글자보다 이쪽이 빠르다 — *영상의 어디를 돌고 있는지* 가 한눈에 보인다.
    [구간 반복] 탭으로 반복할 때도 같은 띠가 나온다
- **구간 편집 칸이 덮어쓰는 건지 새로 만드는 건지 알 수 없던 문제.**
  시각을 직접 쳐 넣고 저장하면 **항상 고른 구간을 덮어썼는데**, 화면 어디에도
  그 말이 없어서 "왜 계속 같은 줄만 바뀌지" 가 됐다.
  - 편집 칸 맨 위에 **제목**이 붙는다 — `구간 02 편집 — [저장] 은 이 구간을 덮어씁니다` /
    `새 구간 — 시각을 적고 [새로 추가]` / `3개 선택됨 — Del 로 지울 수 있습니다`
  - **[새로 추가]** 버튼이 생겼다. 적어둔 시각으로 구간을 **하나 더** 만든다
    (고른 구간을 띄워놓고 누르면 복제가 된다)
  - **[저장]** 은 고른 구간이 있을 때만 켜진다. 무엇을 덮어쓸지 정해지지 않았으면
    누를 수 없어야 한다
  - `Enter` 는 **지금 켜져 있는 쪽**을 누른다 (고른 구간이 있으면 덮어쓰기, 없으면 추가)
- 테마를 바꿔도 A-B 표시 글자 색이 예전 테마로 남던 문제.
  코드에서 넣은 색은 `DynamicResource` 와 달리 한 번 박힌다 — 테마를 적용할 때 다시 칠한다

#### Design notes
- **상태를 한 군데에만 표시하면 그 한 군데를 안 보는 사람에게는 없는 것이다.**

#### Design notes
- **왜 자막 트랙이 아니라 별도 탭인가.** 처음에는 손으로 만든 구간을
  `<영상이름>.mine.srt` 로 저장해 자막 트랙인 것처럼 끼워 넣으려 했다. 두 가지가 걸렸다 —
  (1) 받아쓰기·진도·오답노트·북마크가 전부 **'몇 번째 자막 줄'** 을 키로 물려 있어서,

  (2) README 의 "원본 영상 폴더에는 아무것도 쓰지 않습니다" 약속을 깨야 한다.
  별도 탭 + DB 저장이면 둘 다 생기지 않는다. 구간은 번호를 저장하지 않고
  **시작 시각 순으로 그때그때 매긴다**
- **자막 구간 · A-B · 구간 탭 셋 중 하나만 켜진다.** 같은 시간 축을 세 갈래가 다투면
  지금 무엇이 도는지 알 수 없다. 어느 하나를 켜면 나머지는 놓아준다 (0.8.24 와 같은 규칙)
- **담자마자 재생하지는 않는다.** 여러 구간을 연달아 담는 일이 잦은데
  담을 때마다 소리가 나면 방해가 된다. 고르기만 하고 재생은 사용자가 누를 때

  그러면 **아이디가 틀렸는지 비밀번호가 틀렸는지 구분할 수가 없다.**
  아이디는 메일 주소라 비밀이 아니고 기록은 본인 PC 에만 남으므로,
  아이디만 풀어 `C: 아이디 → 'xxx'` 로 적고 비밀번호는 그대로 가린다.
  안전 기본값 — 서버가 아이디를 물은 **직후 줄**만 풀고 나머지 `C:` 줄은 무조건 가린다.
  `AUTH PLAIN` 은 `\0아이디\0비밀번호` 라서 가운데만 꺼내고, 형태가 다르면 전부 가린다
- **네이버 앱 비밀번호가 "한 번만 보이는 자동 생성 12자리" 라는 점을 안내에 추가.**
  직접 정하는 값으로 오해하면 아무 값이나 넣고 계속 `535` 를 보게 된다
- 인증 거부 안내에 **계정 칸이 메일 주소인데 로그인 아이디가 다른 경우**를 추가.
  네이버는 부계정·별명 주소를 쓸 수 있고 SMTP 는 로그인 아이디를 받는다
- **[앱 비밀번호 발급 페이지 열기] 버튼 추가.**
  SMTP 를 켜는 화면과 앱 비밀번호를 받는 화면은 **서로 다른 사이트**다
  (네이버는 `mail.naver.com` 과 `nid.naver.com`). 하나의 `[설정 페이지 열기]` 로는
  둘 중 하나로밖에 못 보내서, 2단계 인증을 켠 사용자가 길을 잃는다.
  프리셋에 `AppPasswordUrl` 을 추가하고 버튼을 나눴다
- **네이버 안내를 정정.** "2단계 인증을 쓰면 애플리케이션 비밀번호" 라고만 적혀 있어
  2단계 인증이 **필수인 것처럼 읽혔다.** 실제로는 SMTP 에 필수가 아니고,
  켜면 오히려 로그인 비밀번호가 통하지 않게 된다. 발급 경로
  (네이버ID → 보안설정 → 2단계 인증 [관리] → 애플리케이션 비밀번호 관리 → [생성하기])
  를 그대로 적고, 필수가 아니라는 문장을 명시
- **인증 거부 메시지를 "무엇이 정상이었는지" 부터 말하도록 고쳤다.**
  통신 기록으로 확인한 결과 연결 · TLS · 인증 방식 협상은 전부 정상이고,
  아이디 두 형식과 서버가 제시한 인증 방식을 모두 거친 뒤의 거부였다.
  그래서 "로그인이 거부됐습니다" 대신 **앱 설정이 아니라 계정 쪽 문제**임을 못박고,
  SMTP 사용 설정 → 2단계 인증(앱 비밀번호) → 비밀번호 오타 순으로 안내한다

#### Fixed
- **네이버 `535 5.7.1 Username and Password not accepted` 대응 — 인증 방식 제한.**
  MailKit 은 서버가 제시한 인증 방식 중 하나를 골라 쓰는데,
  서버가 `XOAUTH2`(토큰) 나 `NTLM`(윈도우 계정) 을 먼저 내밀면
  비밀번호를 들고 엉뚱한 방식으로 로그인을 시도하다 거부당한다.
  비밀번호 로그인만 쓸 것이므로 `XOAUTH2` · `NTLM` · `GSSAPI` · `ANONYMOUS` 를
  후보에서 빼고 `LOGIN`/`PLAIN` 만 남긴다
- **메일 전송 실패 — "The specified string is not in the form required for an e-mail address".**
  SMTP 로그인 아이디를 보내는 사람 주소로도 써버렸다.
  네이버는 아이디가 `tohinata` 처럼 도메인이 없어서 주소로 쓸 수 없다.
  `보내는 주소` 칸을 따로 두고, 비워두면 받는 주소를 쓰도록 변경
- **메일 전송을 MailKit 으로 교체.** .NET 기본 `SmtpClient` 는
  465(암시적 SSL)를 지원하지 않고 실패 이유도 뭉뚱그려 던져서
  무엇을 고쳐야 할지 알 수 없었다. 이제 587(STARTTLS)·465(SSL) 둘 다 되고,
  인증 실패 · TLS 실패 · 서버 거부 · 연결 실패를 구분해 **서버 응답까지** 보여준다
- 로그인 실패의 가장 흔한 원인(**메일 서비스에서 SMTP 사용이 꺼져 있음**)을
  서비스별로 안내. 서비스를 고르면 설정 화면에 미리 표시하고, 실패 메시지에도 붙는다
- 받는 주소를 넣으면 **로그인 아이디를 자동으로 채운다**
  (네이버는 `@` 앞부분만, Gmail·Outlook 은 전체 주소)
- **로그인 실패 시 아이디 형식을 바꿔 한 번 더 시도한다.**
  아이디만 적었으면 전체 주소로, 전체 주소로 적었으면 아이디만으로 재시도하고,
  다른 형식으로 성공하면 어떤 값으로 됐는지 알려준다.
  이렇게 하면 "아이디 형식이 문제인가?" 라는 변수가 사라져서
  남은 원인이 SMTP 사용 설정 또는 비밀번호 둘로 좁혀진다
- 서비스별 **[설정 페이지 열기]** 버튼 — 네이버 POP3/IMAP 설정,
  Google 앱 비밀번호 발급 페이지 등을 브라우저로 바로 연다
- **콤보박스 내용이 보이지 않던 문제.**
  `ComboBox` 의 선택 영역과 항목은 `ContentPresenter` 가 문자열을 `TextBlock` 으로
  만들어 그리는데, 이 `TextBlock` 이 앱 전역의 암시적 `TextBlock` 스타일(밝은 글자)을
  그대로 먹어서 **흰 배경에 흰 글자**가 됐다. 암시적 스타일의 Setter 는 상속값을 이기므로
  `ComboBox.Foreground` 만 바꿔서는 소용이 없다.
  `Style.Resources` 로 콤보박스 안쪽 `TextBlock` 만 따로 눌러 해결.
  자막 트랙 · 메일 서비스 · 마이크 · Whisper 모델 목록이 전부 이 영향을 받고 있었다
- **네이버 비밀번호 안내가 틀렸던 것.** "네이버는 앱 비밀번호가 필요하다" 고 적었는데,
  2단계 인증을 쓰지 않으면 **로그인 비밀번호 그대로** 쓴다 (앱 비밀번호는 존재하지도 않는다).
  칸 이름을 `앱 비밀번호` → `비밀번호` 로 바꾸고 서비스별 안내를 정정

  Value 변경 자체로 이동하도록 바꿔 클릭·드래그·키보드 모두 동일하게 동작
- 사전 조회 실패 시 오류 문구가 단어장의 "뜻" 으로 저장되던 문제
- 자막 패널 헤더에서 시간 텍스트와 [자막 보기] 체크박스가 겹치던 문제

### 0.5.0 — 2026-09-17

#### Added
- **영어 기준 채점 규칙**과 [채점] 설정 탭.
  기준은 "귀로 구분되는 것은 채점하고, 귀로 안 들리는 것은 넘어간다"
  - 채점: 축약형 (`it's`≠`its`, `we're`≠`were`, `can't`≠`cant`), 동음이의어
  - 넘어감: 영·미 철자(`colour`=`color`), 감탄사(`uh`, `um`, `hmm`),
    숫자/수사(`20`=`twenty`), 하이픈, 붙여쓰기(`a lot`=`alot`), 악센트, 대소문자
  - 문장부호는 기본 제외, 필요하면 켤 수 있음
- **자막 표기 걷어내기** — `[SIGHS]`, `(LAUGHING)`, 줄머리 대시,
  `JOHN:` 화자 표기, `♪` 제거. 효과음만 있는 줄은 통째로 건너뜀
- 일본어·중국어 자막용 **글자 단위 채점** (띄어쓰기가 없어 한 글자만 틀려도
  0점이 되는 문제 해결). 한국어는 띄어쓰기가 있으므로 단어 단위 유지

#### Changed
- 정답에 없는 단어를 더 쓰면 감점되도록 정확도 계산 변경
  (아무 말이나 덧붙여 100% 가 나오던 문제)

  - 자막 목록에 `★` 표시, 담기지 않은 줄에는 흐린 `☆` (클릭 가능 표시)

### 0.3.0 — 2026-09-17

#### Added
- **MKV 자체 파서** (`Services/MatroskaReader.cs`) — EBML 을 직접 읽어
  **ffmpeg 없이 내장 자막을 추출**
  - `S_TEXT/UTF8`(SRT), `S_TEXT/ASS`·`SSA`, `S_TEXT/WEBVTT` 지원
  - 이미지 자막(`S_HDMV/PGS`, `S_VOBSUB`)은 사용 불가로 표시
  - unknown-size 세그먼트(스트리밍으로 만든 MKV)도 처리
  - **한 파일에 자막이 여러 개(jpn·eng·kor)여도 한 번의 훑기로 전부 추출**하고
    트랙별로 캐시 → 두 번째부터 트랙 전환이 즉시

#### Changed
- ffmpeg 은 이제 **선택 사항**. mp4 등 MKV 가 아닌 컨테이너의 내장 자막,
  `.ass`/`.vtt` 외부 자막 변환, Whisper 에만 필요
- 자막 목록에 `(ffmpeg 필요)` 표시 추가

#### Fixed
- **VLC 가 영상에 자막을 그려 정답이 미리 보이던 문제.**
  `SetSpu(-1)` 은 트랙이 준비된 뒤에만 먹으므로 `--no-spu` 로 시작하도록 변경
- 크기 조절 경계선이 영상이 아니라 **재생 바를 늘리던 문제.**
  `GridSplitter` 는 바로 인접한 행을 조절하는데 그 행이 재생 바였다.
  영상과 재생 바를 한 행으로 묶고, 두 행을 모두 별(`*`) 단위로 바꿔
  창 크기를 바꿔도 비율이 유지되게 함
- `a.mkv` 옆의 `ab.srt` 를 자막 후보로 잘못 잡던 문제 (구분자 확인 추가)

#### Changed
- 재생 속도 범위를 0.5x ~ 3.0x, 0.5 단위로 변경. `X`/`C`/`Z` 단축키 추가

### 이 문서 관리 방법

- 작업할 때는 `[Unreleased]` 아래에 먼저 적고, 배포 시점에 버전 번호와 날짜를 붙인다.
- 분류는 **Added**(추가) / **Changed**(변경) / **Deprecated**(예정된 제거) /
  **Removed**(제거) / **Fixed**(수정) / **Security**(보안) 만 쓴다.
- 버전을 올릴 때는 `src/MidDictation/MidDictation.csproj` 의
  `Version` · `AssemblyVersion` · `FileVersion` 을 같이 고친다.
  설정 창의 [정보] 탭이 이 값을 그대로 읽어 보여준다.
- 버그 수정은 **무엇이 잘못됐는지보다 왜 그랬는지**를 한 줄 남긴다.
  같은 함정을 다시 밟지 않기 위한 기록이다.
- 버전 기준
  - **MAJOR** — 저장된 설정이나 DB 를 못 읽게 되는 변경
  - **MINOR** — 기능 추가, 화면 구성 변경
  - **PATCH** — 버그 수정, 문구 수정
